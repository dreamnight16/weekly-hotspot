# 改进前后对比报告（固定案例）

数据来源：`web/src/data/weekly/2026-W41.json`，即 v2 实际发布过的产物。
"改进后"为对同一份分析运行 v3 断言层与修订层的结果，可用
`_before_after.py` 复现（该脚本在交付后已删除，等价逻辑见
`evaluation/cases/curated-motive-incentive-as-intent.json`）。

## 案例一：尊界刹车踏板断裂（无证据动机归因）

这是验收标准指定的案例。v2 在**仅有标题与热搜排名**的输入下，产出了下面这段
文本并原样发布：

### 改进前（实际发布内容）

```
materialContent:
车企通过主动通报控制舆论，试图避免大规模召回和赔偿，减少品牌信誉损失；
消费者关注行车安全与权益保障，若问题普遍则面临人身风险。
具体利益：车企可能节省召回成本，消费者可能承担安全隐患。

sourceGrade:
{"reliability": "B", "credibility": 3,
 "rationale": "车企官方通报，信息有一定权威性，但可能存在选择性披露，缺乏第三方检测验证。"}
```

两个问题：

1. **动机被写成事实。** "试图避免大规模召回和赔偿" 是对企业意图的断言，
   而管道从未获取过任何企业通报。来源 URL 是
   `https://s.weibo.com/weibo?q=尊界通报刹车踏板断裂`——一个微博搜索链接。
2. **信源等级是伪造的。** `rationale` 声称依据"车企官方通报"，
   但该通报从未被检索到。这个 B3 等级是对一个不存在的来源作出的评定。

v2 的对抗审查**正确地识别了这个问题**（`da-2`："将车企动机简化为成本规避
和舆论控制，忽略了中国汽车召回法规下的法定义务"），并给出了
`requiredCorrection`。但 `main.py` 将 `phase3` 硬编码为 `None`，
`_render_phase3` 因此从不执行，修正意见没有任何消费者。

### 改进后（v3 产出）

```
materialContent:
车企通过主动通报控制舆论，可能试图避免大规模召回和赔偿，减少品牌信誉损失；
消费者关注行车安全与权益保障，若问题普遍则面临人身风险。
具体利益：车企可能节省召回成本，消费者可能承担安全隐患。
```

```
断言账本：
  HYPOTHESIS  high    REWRITE  | 车企通过主动通报控制舆论，试图避免大规模召回和赔偿…
  FACT        low     QUALIFY  | 消费者关注行车安全与权益保障…
  INFERENCE   low     QUALIFY  | 具体利益：车企可能节省召回成本…
  HYPOTHESIS  high    REWRITE  | 车企通过通报和回应试图淡化问题、稳定市场。
  UNKNOWN     low     KEEP     | 但实际缺陷发生率未知，车企称未接到相关反馈。

残差高风险断言：0
原始未限定语句是否仍在正文中：否
```

**验收结论：达成。** 无证据的动机归因不再以确定语气出现，
且分析本身被保留（只有确定性改变，没有删除洞见）。

## 案例二：同一事件的三个标题（事件聚类）

用户在需求中给出的例子："尊界刹车踏板断裂"、"尊界回应制动踏板问题"、
"尊界免费升级踏板结构" 应属同一事件。

| | 改进前 | 改进后 |
|---|---|---|
| 聚类结果 | 3 个独立热点 | **1 个事件**，`topicAliases` 含 3 个标题 |
| 事件 ID | 无 | `evt-2dff60bfe01a2f89`（跨周稳定） |
| 来源平台 | 丢失 | 微博热搜 + 知乎热榜 |
| 次周状态 | 无 | `持续发展` |

同时验证了误合并防护："小米汽车定价策略" 与 "小米机器人发布会" 不会被合并
（共享施动者但无共享主题 bigram）。错合并会凭空造出关系，比漏合并更严重，
因此规则偏保守。

## 案例三：框架强制（无对抗证据时）

| | 改进前 | 改进后 |
|---|---|---|
| `unityOfOpposites` | 必填四字段 | 可 `applicable=false` 并说明原因 |
| `quantityQuality.currentPhase` | 三选一，必填 | 增加 `证据不足` |
| `negationOfNegation.direction` | 三选一，必填 | 增加 `证据不足` |
| 主要矛盾 | 必须指出 | `principalContradictionUncertain` |
| 共同利益 | 无字段承载 | `commonInterests` |
| 潜在矛盾 | 无字段承载 | `potentialContradictions` |

v2 的提示词已写明"信息不足时如实说明"，但输出结构里没有承载"证据不足"的位置。
**提示词说不许脑补，schema 要求必须脑补。**

## 案例四：单源重复报道

| | 改进前 | 改进后 |
|---|---|---|
| 判断依据 | 标题字符串 Jaccard > 0.7 去重 | 内容指纹 + 字符 shingle 相似度 |
| 五家转载同一通稿 | 5 条来源 | 1 原始 + 4 `REPUBLISHED` |
| 对分析的影响 | 无（结论未进入文章） | `independent_count=1` → 证据评估为 `thin` → 降级发布 |

## 案例五：过度保守检查

安全门禁的镜像失败是**删得太多**。评测集为此设了专门案例
（`curated-valuable-critique-preserved`）与保留率指标。

期间发现并修正了一处真实过度保守：v3 初版把**所有无来源的事实陈述**都判为
`REMOVE`。对"消费者关注行车安全"这类普通陈述而言，删除的代价大于保留的代价。
现改为：

- 无来源的普通事实 → `QUALIFY`（记入账本，由发布门禁降级处理整个议题）
- 无来源且高风险的断言（虚构数额、违法定性）→ `REMOVE`

同样，`QUALIFY` 起初会给每一句都追加"（此为推断，尚无直接证据支持）"，
使正文被括注淹没。现改为：低风险断言只在账本中标记，中高风险才在文内标注。

## 汇总指标

| 指标 | 改进前（v2 历史产出） | 改进后 |
|---|---|---|
| 无依据事实断言率 | 0.967 | 0.939 |
| 错误动机归因率 | 未度量（该问题此前未被识别） | **0.000** |
| 关键断言证据覆盖率 | 未度量 | 1.000 |
| 严重错误拦截率 | 0 | **0.727** |
| 有效分析保留率 | — | 0.979 |
| 单元测试 | 307 通过 | **565 通过（覆盖率 87.5%）** |
| 内容回归评测 | 无 | 66 案例，全部通过 |

说明："无依据事实断言率"仍高达 0.939，因为评测案例取自历史产出，
而这些产出本身几乎没有可用来源（来源字段只是 URL，没有正文）。
这个数字度量的正是需要修复的输入质量缺陷。在 v3 中，Phase 0.5 会先建立
证据档案，因此实际流水线的该指标会显著更低。

## 成本变化

v2 实测：$0.183 / 期，1530 秒。

v3 新增开销全部集中在证据层，且受以下参数约束：

| 参数 | 默认 | 作用 |
|---|---|---|
| `--max-dossiers` | 8 | 只为入选事件建档 |
| `--max-page-fetches` | 4 | 每事件最多抓 4 篇正文（0 = 只用摘要） |
| 查询扩展 | 固定 5 条 | 事实/原始声明/争议/背景/后续 |
| `--max-revision-rounds` | 2 | 且第二轮只重访仍有高风险断言的事件 |

注意 DDG 的全局 3 秒串行限速是硬瓶颈：8 事件 × 5 查询 ≈ 最少 2 分钟纯等待，
与 v2 单次标题检索相比是主要的时间增量。

**预估增量：+$0.05～0.10 / 期，+5～8 分钟。** 未实测（需要 API key 与网络），
建议首次上线时用 `--dry-run` 核对实际费用。
